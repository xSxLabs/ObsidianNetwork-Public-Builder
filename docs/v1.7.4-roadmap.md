# xSxLabs Network Storage v1.7.4 – feature specification

Status: **requirements / planned**, unless a specific feature is separately confirmed by a successful build and in-game test. Build 398 is the immutable v1.7.3 green freeze commit (`d2d1739ff430b1944e5d0214386db3b89eeae0cd`). New features stay on `v1.7.4`; the user explicitly prioritized an AE2-style red JEI missing-ingredient / clickable partial recipe-transfer **hotfix on `v1.7.3`**. This hotfix must never modify the secured Build-398 freeze branch. Keep existing registry IDs and saved-world compatibility.

## 1. WIP systems inherited from v1.7.3

- Hologram Terminal: improve its 3D map so all visible terrain layers and proportions work; remove the NETWORK mode from the eventual interface. Keep it hidden as WIP in the meantime.
- Printer, saved Schematic / Blueprint and Schematic & Quill: fix speed upgrades, visible movable/rotatable 3D placement preview, missing-block one-step skip, and air skipping. Keep hidden as WIP until reliable.

## 2. Multiblock nuclear reactor

- Inspired by Big/Extreme Reactors gameplay, but use original xSxLabs models, assets and implementation.
- Valid exterior dimensions: **minimum 5×5×5, maximum 64×64×64**. Validate casing structure, interior, controller and ports; use distinct casings, reactor glass, control rods / fuel rods, coolant interfaces, and other functional components appropriate to a complete reactor.
- Real uranium fuel chain: uranium ore -> raw uranium drops -> smelted uranium ingots -> uranium fuel rods. **Two uranium ingots vertically craft one uranium rod**, like the vertical-stick crafting pattern but with two ingots.
- Fuel rods must accept *all compatible uranium ingots* from other mods using a shared NeoForge common item tag, with explicit compatibility tests.
- Reactor **consumes uranium rods and water** to run; cooling materially affects production, operation and/or safety. Real item-cable fuel handling and fluid-cable water handling, with accessible input/output ports, FE cable output, persisted state and GUI.
- Power output grows with reactor size and is intentionally somewhat above Big Reactors' corresponding values; exact numeric balancing and caps to be calibrated, not invented as implemented. Server-authoritative multiblock state, scalable tick cost, visible multiblock/operation animations.

## 3. Multiblock Powerbank

- Valid sizes **3×3×3 minimum to 3×3×12 maximum** (the cross-section stays 3×3).
- Capacity **10 billion FE to 100 billion FE** according to size; use `long` and safe arithmetic, never int-overflow.
- Powerbank casings and energy input/output ports; compatible with existing xSxLabs energy cables, GUI, transfer rate limits/updates, persistent charge, correct assemble/disassemble handling.

## 4. Building guidebook

- In-game guidebook containing *build plans / layer-by-layer visual diagrams* for valid reactor and Powerbank layouts and sizes, component functions and connection instructions. Ensure it is obtainable and has working GUI/navigation.

## 5. Electric water pump

- Produces/extracts water for the reactor, connects to fluid cables/ports, has real working speed-upgrade effects, avoids unloaded-chunk and infinite-loop scans, and supports a useful machine GUI where needed.

## 6. MekaSuit-inspired automatic nutrition system

- Add a **Feeding Upgrade Card** for the MK power armor (at least helmet integration, subject to existing armor upgrade-slot conventions).
- With the card installed and enough stored paste, the wearer is automatically fed **at the first hunger point lost** (Mekanism MekaSuit-style Nutritional Injection behavior); do not require hunger to drop multiple points. No food duplication or creative bypass; apply effects server-side and persist paste in the helmet.
- Add **Nutrinator** machine that converts every supported edible food into **NutriPaste**, with sensible nutrition conversion and modded-food compatibility.
- Nutrinator has a **1,000,000-bucket internal NutriPaste tank** (use overflow-safe fluid units and long storage), item/food input, dedicated speed-upgrade slot, dedicated helmet slot that fills the inserted helmet's paste storage, synchronized GUI and persistent inventories/contents.
- Do not conflate FE with food/paste. Ensure stored-paste depletion is proportional to hunger restoration, visible tank/helmet levels, and valid item-cable automation.

## 7. Network Vision x-ray refinement (user requested)

- When Network Vision is enabled and its Power Armor upgrade card is installed, show the **real xSxLabs network cables and attached importer/exporter blocks even through solid intervening world blocks** (depth-independent, visibly overlaid wireframe or translucent highlight).
- No unrelated terrain, machines, networks, inventories, or non-network blocks may appear in the overlay. This is **not a general X-ray mode**; reveal only own cables and intended importer/exporter targets, including cable segments concealed behind facades.
- Correct world alignment and facing, bounded loaded-chunk scanning and render cost, multiplayer visibility restrictions, action-wheel toggle, and immediate disappearance on disable/card removal. Client rendering only; do not modify collision, block states, connections, ownership or transport.

## 8. Portal A horizontal placement (user requested)

- Portal A must be placeable on **all four horizontal orientations** (north, east, south, west) instead of only one/two facings. Orientation must match the targeted supporting block face/placement direction.
- Portal A is still a 1-block-wide × 2-block-high visible portal, persistent and selectable by ID. Portal B remains temporary, links to the chosen A, and disappears after transport.
- Persist facing and link, render both front/back correctly for each orientation, enforce 2-block clearance/support/collision and retain previously placed portals across save/reload. Cover all four directions in tests.

## Acceptance and release safety

- Functional NeoForge dedicated-server and client compilation, game tests, persisted-state tests, nonduping transport and protection against chunk unloads.
- GUI/animation client tests and actual user in-game confirmation before declaring the WIP systems complete.
- Keep the immutable **Build 398 / `freeze/v1.7.3-build398-green`** reference unchanged. The separately authorized v1.7.3 JEI crafting hotfix is permitted on the active `v1.7.3` development branch, but is not part of Build 398.
