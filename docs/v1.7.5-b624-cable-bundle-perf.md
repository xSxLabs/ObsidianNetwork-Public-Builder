# B624 – Cable Bundle / Conduit performance without throughput regressions

Scope: v1.7.5 only, Build 617 freeze remains unchanged.

Pre-existing transport optimizations already present:
- ENERGY endpoint capability lookup once per endpoint and dispatch, never cached between ticks;
- topology O(1) node-position membership and live face invalidation;
- ITEM duplicate scan elision with once-per-tick transfer guard;
- reusable enum direction arrays and neighbor positions.

New B624 optimization:
- In the ENERGY Cable Bundle EnergyConduitTicker, reuse the owning bundle's immutable BlockPos once per visited live node instead of fetching the same BE position for every connected face.
- The same BlockPos.relative(d) is still computed for each face; all six directions, chunk/loading checks, capabilities, FE extraction/insert/refund, transaction commits and refresh cadences are untouched.
- Dedicated randomized position equivalence tests (200,000 cases), fail-closed source regression tests, and unchanged inherited ITEM/FLUID/ENERGY/GameTest gates.
- No claim of significant MSPT improvement without a controlled same-world Spark A/B comparison. No per-tick persistent or network-wide cache added.
- Keep existing Cable Bundle installed-cable drops exactly as shipped in Build 617.

This intentionally prefers a low-risk measured hotspot micro-optimization over changing transfer rates or caching unsafe live topology/handler state.
