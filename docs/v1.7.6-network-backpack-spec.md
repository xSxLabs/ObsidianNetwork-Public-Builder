# v1.7.6 – Network Backpack (user-approved specification, 2026-11-02)

## Scope / priority
This is an ADDITIVE v1.7.6 feature. Implement against the current clean `v1.7.6` branch and the reconstructed NeoForge 26.1.x source; do not use legacy/retired `networkstorage-v1.7`, change 1.7.5 freeze, or imply an ingame build is ready until compiled and tested. This document is a specification, NOT a claim that implementation exists.

## 24 equal-function Power Armor color variants
- There are **exactly 24 visually distinct Network Backpacks**, matching the 24 Power Armor MK color variants one-for-one.
- All 24 variants have the SAME capacity rules, one magnet slot, three Storage Cell slots, Curios compatibility, keybind, item-cable support and placement behavior.
- Their differences are strictly model/texture/palette. No capacity/upgrade/stat advantages.
- The generated per-tier 3D assets MUST use the corresponding real original MK texture atlas colors, not a shared generic image.

## Backpack appearance and item placement
- Shape, proportions and wearable silhouette closely inspired by Sophisticated Backpacks (recognizable compact backpack form), but own xSxLabs model and original textures; coherent Network Storage visual style. Render as item, on wearer, and as placed world object; correct model orientation and all-player synchronization.
- Right-click with the backpack **held in the main hand** opens its GUI (not a generic inventory or the connected network).
- **Sneak + right-click aimed at a block while holding**: place backpack on the face/surface of the looked-at block, if permission/space permits. Placement takes precedence over GUI opening.
- Right-click the placed backpack: open GUI. **Sneak + right-click the placed backpack**: pick it up as the SAME backpack item, with all items, cells, magnet, mode, filter, NBT/data components and identity preserved. Interaction with placed backpack takes precedence over placing another.
- When physically broken, safely return the backpack with its contents exactly once (or another strictly lossless safe behavior), never drop both embedded items and a populated backpack. Respect server protections and loaded chunks.
- No invisible duplicate inventory and no content loss across save/reload, dimension transitions, death, placement, pickup or concurrent UI/cable activity.

## Wear and hotkey
- Wearable as **normal chest equipment** in the vanilla CHEST armor slot OR in the optional **Curios back slot**. Curios integration must be optional: no crash when mod is absent. Wearing it in CHEST uses the slot, and must not silently replace an existing chestplate.
- Registered **rebindable Open Backpack** key mapping under xSxLabs in Controls; default UNBOUND to avoid conflicts, player may assign any key.
- Server-validated hotkey opens an actually worn backpack from vanilla CHEST and/or Curios back; don't depend on holding the item in hand. If both contain different backpacks, use a deterministic order (vanilla CHEST first, Curios back second). The held right-click path remains supported.
- Stop invalid remote opens; do not trust a client-selected index or fake data.

## Storage and UI
- **Exactly three (3) slots for existing Network Storage Storage Cells**, PLUS **one (1) separate Magnet Upgrade slot** = FOUR dedicated side slots. No extra internal storage capacity besides the three installed cells. Do not confuse this with the earlier 2-cell proposal.
- Capacity is determined by the REAL three installed cell types, limits and aggregate currently supported item serialization; sum their capacities under the existing storage rules, including applicable type/byte limits. Three compatible 256k capacity cells nominally add to 768k. Without a cell, item capacity = zero.
- **Final user-approved Backpack GUI (2026-11-02): absolutely NO crafting grid or crafting output and NO autocrafting button.** The main panel contains a real storage-item list with accurate stack counts, the same search behavior as the existing Crafting Terminal **including its clickable Autofocus ON/OFF button**, and the Sort button. Player inventory is below, with lossless deposit/withdrawal interactions.
- **One separate module panel visibly to the RIGHT of and OUTSIDE the main Backpack GUI**, with a gap: Magnet Upgrade, Cell 1, Cell 2, Cell 3, in that order. The four side slots are real, not fake, and never share the central item-list area. Display used/total and enforce exact item/cell transfer rules.
- Each slot accepts only its own correct registered upgrade/cell type; no arbitrary items or recursive backpacks. Prevent removing/replacing an occupied cell when remaining capacity could not hold its contents; provide unambiguous feedback. Keep cell data intact.
- Backpack is independent of a placed Network Drive; its storage must not automatically merge with external network inventories.

## Magnet upgrade
- A craftable **Network Backpack Magnet Upgrade** can be installed only in the magnet slot; user can turn it ON/OFF in the GUI.
- Supports both **Whitelist** and **Blacklist** with editable item filters (clearly visible current mode); filters match real item identity and preserve stack components where appropriate. Only items passing the active filter enter backpack.
- When active and backpack is held/worn, vacuum nearby item entities directly into the 3 installed backpack cells, respecting capacity, server permissions and attraction distance. Pickup must be atomically limited to inserted amount: leave leftovers in the world; never clone entities or delete overflow.
- OFF or absent upgrade means no magnet pickup. Settings persist on item when placed/collected and through reload. World-placed backpack must not vacuum distant drops by default unless separately specified.

## Item Cables
- When **placed**, expose a NeoForge item-handler capability compatible with existing xSxLabs Item Cables, with extraction of item stacks from the backpack's three cell storage in a lossless, bounded, server-side transaction.
- Cable must not be able to extract the three storage cells, magnet upgrade, GUI ghost filters, or backpack itself. Respect simulations, side access, full destinations, partial transfers and no duplication/re-entrance.
- When worn/held, backpack is not a block endpoint for cables.

## Acceptance gates (no premature test JAR)
1. Both right-click and hotkey opens; shift-place and shift-pickup preserve all content.
2. Exactly 1 magnet + 3 cell slots; mixed sizes and accurate total, filled/empty boundaries and cell removal safety.
3. Magnet toggle, whitelist, blacklist, partial-insertion safety, world item remainder.
4. Cable extraction with sink full/partial, chunk unload/reload; no loops or duplication.
5. Vanilla CHEST and optional Curios back slot; operation in BOTH configurations; multiplayer permissions and rendering.
6. Actual NeoForge full compile, client/menu/game tests and no regressions in Power Armor, Crafting Terminal or existing storage; verify NO 3x3 crafting UI, functional Search + Autofocus + Sort and the detached right-side module slots.
7. Release ingame JAR only after complete v1.7.6 package is integrated, not on the strength of this specification alone.
