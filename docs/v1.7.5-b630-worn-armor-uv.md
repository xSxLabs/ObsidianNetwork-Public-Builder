# B630 – Worn Armor → Animated Armor exact pixel remapping

Baseline: Build 629 GREEN, branch v1.7.5. Freeze/v1.7.4-build617 untouched.

Root cause: the vanilla worn equipment references 24 separate 64×32
textures/entity/equipment/humanoid and humanoid_leggings sprites. The B629
GeckoLib 128×128 texture was a *separately painted synthetic atlas*, so colors,
face details and armor-side patterns never matched the actual worn items.

Fix:
- In each of the 24 GeckoLib 128×128 entity atlases, composite the real
  fully rendered worn 64×32 humanoid PNG into pixels (0..63,0..31) and the
  real leggings PNG into (0..63,32..63); alpha and RGBA are copied exactly.
- UV-map original worn helmet front to the ONE moving faceplate; vanilla
  head back/top/side panels map to original equipment artwork.
- UV-map the external torso front, left/right chest plates and the precisely
  split rear left/right shells from the corresponding canonical torso UV
  rectangles (front 20..28,20..32; back 32..40,20..32).
- UV-map continuous real upper/lower arm, shoulder, thigh and boot regions
  to their respective animated bones, no flat-color texture replacements.
- The original extra visor cuboid is removed from render geometry to avoid
  duplicate nonmatching eye decals; the visor bone/rig remains for compatibility.
- Hinges, rails, gaskets and reactor details reuse small real equipment pixel
  regions on their outward surfaces; newly exposed inner faces retain
  color-matched manufactured-metal detail.
- All 24 built atlases match worn PNGs pixel-for-pixel; pre/post SHA-256 guard
  for EVERY animation JSON AND Java runtime file ensures zero motion or
  gameplay alterations. Recall trajectory, stages, timings and entity logic
  remain B629 byte-identical.
- A separate 24-tier pixel identity + UV coverage + no-second-mask +
  no-timing-drift gate runs before full NeoForge compile.

Note: original worn and animated mesh shapes are not mathematically identical.
Actual in-game video comparison is still necessary for precise 3D silhouette
and UV orientation, which the offline test cannot prove.
